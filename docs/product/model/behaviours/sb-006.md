when: the settlement plan is calculated
then:
  - The plan uses a greedy creditor-debtor matching approach
  - Creditors and debtors are sorted by participant ID using ordinal comparison for deterministic output
  - The result is the minimum number of transfers to zero out all balances
  - If all balances are zero, the result is an empty list

## Intent

Make concrete the settlement algorithm: produce the fewest transfers needed to settle all debts, with deterministic ordering so the same balances always yield the same plan.

## Boundaries

This behaviour covers the settlement plan calculation only. Recording an actual payment (UC-007) is a separate user action that may or may not follow a suggestion. Partial payments are allowed and will produce a new settlement plan on the next calculation.
